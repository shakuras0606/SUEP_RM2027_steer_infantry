# MC02 四舵轮底盘移植方案

建议沿用 MC02 的命令消息、FreeRTOS 任务、DJI 电机闭环和 FDCAN 驱动，把四舵轮接在 `ChassisInit()` 与 `ChassisTask()`。第一版以车体坐标系下的前进、横移、转动为目标。四角各有独立转向、独立驱动和可连续回转的舵轴，是本方案的机械假设。电机部分以 M3508 行走、GM6020 直驱转向为例，实际选型和传动待确认。

分析基线为本地 `14ea0f4` 所在工作区和参考仓库 `5b7095e`。本地原工程已用现有 Makefile 在独立临时目录全量构建，生成 ELF、HEX、BIN，有既有编译和链接警告。本次验证止于构建，机械参数、总线负载与控制响应均待实测。

## 3. 接口、单位和计算顺序

建议在底盘层增加 `swerve.c/.h`。解算函数只接收车体速度、轮组几何和每组当前舵角，输出四对目标舵角与有符号轮缘线速度。将新增 C 文件加入 Makefile 的 `C_SOURCES`。`chassis.c` 负责模式、反馈、使能与单位换算。模块级 PID 和 CAN 发送各自保留一个执行入口。

1. **命令入口统一单位。** 建议解算内部约定 x 向前、y 向左、俯视逆时针为正。线速度用 m/s，角速度用 rad/s，舵轴位置和轮半径用 m。现有文件头定义 y 向右，尺寸宏用 mm，遥控量直接乘 10，`NO_FOLLOW` 强制 `wz=0`，`ROTATE` 写死 `wz=4000`。在命令入口按模式明确量程、转换轴向及单位，云台坐标旋转只执行一次。原有 350 mm 轴距、300 mm 轮距和 60 mm 轮半径是模板值。
2. **按轮心速度逆解。** 设第 i 个舵轴相对选定旋转中心的位置为 `(xᵢ,yᵢ)`，常规舵轴与轮心平面投影重合时有 `uᵢ = vx − wz·yᵢ`、`vᵢ = vy + wz·xᵢ`。轮缘线速度为 `hypot(uᵢ,vᵢ)`，目标舵角为 `atan2(vᵢ,uᵢ)`。该轮速度低于死区时，给驱动零速并保持上一有效舵角，初次保持值取真实反馈。
3. **选就近舵角。** 将目标减去**实际轮组角**，把结果折回 ±180°。当误差绝对值超过 90° 时，目标舵向换到相差 180° 的等效方向，驱动速度反号。例如实际 10°、目标 170°，等效舵向是 −10°，只需反转驱动并打舵 −20°。在等效方向切换附近可加小滞回。存在机械限位的舵轴还要检查目标可达性。
4. **换算到两类电机。** 本地 DJI 速度环使用电机轴 `speed_aps`（°/s），内置角度环使用 `total_angle`（连续角度，°）。驱动参考值为 `有符号轮速 / 轮半径 × 驱动减速比 × 180/π`，其中减速比定义为电机转数除以输出转数。直驱舵轴先用各自零位求实际轮组角，再将最短轮组误差换算到电机轴，叠加到当前反馈的连续角上作为参考值。有额外舵向传动时要计入舵向减速比和符号。编码器跨零、方向配置和电机反转标志必须按同一套定义验证，避免重复反号。
5. **对齐后逐步给驱动。** 用优化后的舵角误差 `e`（rad）计算 `max(0, cos(e))³`，按该系数衰减对应驱动轮速，再将超出轮速上限的四轮参考值等比例缩小。轮速限制解决转速饱和，功率限制需要在可获取电机输出和实测功率的层级另做。

## 4. 接电机之前需要解决的问题

- **注册容量。** 单板默认有 4 个底盘电机和 5 个其他 DJI 电机。四舵轮替换麦轮后总数为 13，当前 `DJI_MOTOR_CNT` 为 12，注册末尾直接执行 `dji_motor_instance[idx++] = instance`。若保留整车配置，先按总量调整容量，并把越界检查放在注册和分配之前。若本车仅有底盘，将无实物模块的注册及对应任务调用成对裁剪，保留遥控命令链。本地 BSP 另有整板 16 个 CAN 接收实例上限。[DJI 容量](../modules/motor/DJImotor/dji_motor.h) · [注册逻辑](../modules/motor/DJImotor/dji_motor.c) · [CAN 容量](../bsp/can/bsp_can.h)
- **总线与轮号。** 仅底盘台架可先按 FDCAN1 四驱动、FDCAN2 四转向规划。在默认整车程序中 FDCAN2 已注册三个其他电机和超电，FDCAN3 已注册两个 GM6020。确定接线前，按总线列出所有设备的反馈 ID、发送组、组内槽位和反馈频率。三路外设配置均为经典 CAN，名义 1 Mbit/s；台架测量各路峰值负载、丢帧和发送超时，再定整车拓扑。[FDCAN 配置](../Core/Src/fdcan.c) · [分组映射](../modules/motor/DJImotor/dji_motor.c)
- **零位与反馈有效性。** 直驱绝对编码器可在四轮机械指向车头时分别记录零位。若舵轴有减速机构，且只有电机侧单圈绝对值，掉电重启后可能有多个轮组朝向对应同一读数，需要输出轴绝对编码器或可重复回零。DJI 驱动初始化默认使能，离线回调只记录日志，守护模块注册时在线计数已为正。建议底盘注册后立即置停，确认收到每个轴的首帧和有效命令后再使能。[DJI 初始化与反馈](../modules/motor/DJImotor/dji_motor.c) · [守护模块](../modules/daemon/daemon.c)
- **失联与急停。** 遥控丢失会清空遥控数据，但 CMD 的急停判断未调用 `RemoteControlIsOnline()`，底盘也未检查本次是否取到新命令。把遥控或板间命令超时、舵角反馈失效、手动零力纳入同一输出判定。故障时令底盘八轴输出零，再使能时用新反馈重建目标，复位会造成输出突跳的控制器状态。[遥控离线处理](../modules/remote/remote_control.c) · [CMD 急停](../application/cmd/robot_cmd.c)
- **若实际使用达妙舵电机。** MC02 是主控型号。工程中的 `DMMotorTask()` 当前实现力矩输出，`DMMotorInit()` 还会发送编码器置零命令，默认 `OSTaskInit()` 没有启动 DM 控制任务。选用这一路线时，应先确定驱动模式、反馈角单位、零位保存方式和任务入口，再接舵角目标。[DM 驱动](../modules/motor/DMmotor/dmmotor.c) · [任务入口](../application/robot_task.h)

## 5. 分阶段开发与验收

| 阶段 | 实施内容 | 进入下一阶段的判据 |
| --- | --- | --- |
| A　离线解算 | 建立轮组配置表和纯解算函数。覆盖前进、左移、正自旋、平移叠加旋转、零速、编码器跨零。 | 前进时轮地速度全向前，左移时全向左，纯自旋时各轮速度均与其半径垂直。舵角 359°→1° 选择 +2°，0°→180° 优先保持舵向并反转驱动。 |
| B　单模组架空 | 先记录 CAN 反馈和零位。驱动保持零输出，调好舵向内速度环，再调外角度环；随后低速验证驱动方向和换算。 | 任意朝向上电均能识别轮组方向。正、反跨零均走短弧。单驱动正转对应实物定义的前进方向，实测转速与换算一致。 |
| C　四模组架空 | 逐组核对物理位置、总线和 ID，依次下发直行、横移、旋转、小幅混合指令，并分别测试停机与断开输入。 | 四组均有独立有效反馈和相应输出。手动急停、遥控失联和单舵反馈超时均能撤销驱动命令。恢复时不会重放故障前目标；记录实际周期和停机延迟。 |
| D　低速落地 | 车体系下依次测直线、横移、定点旋转，再测平移与旋转组合。记录舵角目标/实际、驱动速度目标/实际、输出及供电功率。 | 各轴运动方向符合操纵定义，纯旋转中心与几何设定相符。依据记录再整定斜坡、余弦补偿及限幅，最后接入需要的坐标跟随和整车功率控制。 |

进入实现前，先从机械图和接线表确认**轮组数量及位置、驱动与转向电机和电调的型号及齿比、舵角传感器所在轴及可转范围、板型与现有 CAN 接线**。各轮零位可以在阶段 B 实测后填写。
